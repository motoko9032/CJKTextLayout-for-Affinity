# Affinity CJK Typography Toolkit

**Version:** 0.5.6  
**Target:** Affinity by Canva desktop scripting API (SDK 3.3.x)  
**Platform:** macOS / Windows desktop  
**License:** MIT

## 0.5.6 更新

- 连续标点挤压豁免破折号字符，包括中文常用的 `——`。

## 0.5.5 更新

- 增加默认关闭的“修复已有字距”选项，可将所选文本范围的 `CharacterSpacing` 和 `ManualKerning` 归零，处理此前已写入文档的异常字距。
- 重置会清除所选范围内原有的手工字距；建议先复制文档，确认无误后再应用。重置和其他勾选的调整合并为单次撤销操作。

## 0.5.4 更新

- 移除行首标点检测和挤压，避免影响正常排版。
- 保留中西文直接相邻字距调整和连续标点挤压。
- 连续标点挤压豁免省略号（`……`、`‥` 及连续三个以上的半角/全角句点）和汉字；汉字不会作为连续标点挤压目标。

## 0.5.3 更新

- 格式命令使用 Affinity SDK 的 `StoryRange` 实例创建文本子选区，避免将普通对象传入原生文本选区 API 后整批命令失败。
- 命令失败时明确报告“未应用”，不再显示成功但调整数为 0 的结果。

## 0.5.2 更新

- 节点 `StoryRange` 超出可读 Story 文本末端时，将候选检测限制在实际可读范围，避免生成越界格式目标。
- 将段首重复的「识别为跨段对话引号延续，减少中文小说对白的误报。
- 在构建撤销命令前校验格式目标范围；越界目标单独报告并跳过，避免无效位置使整批调整失败。

## 0.5.1 更新

- 兼容 Affinity 返回的 `StoryRange` 末端比可读文本多 1 个位置的情况；候选扫描使用可读文本范围，不再因末端边界导致所有排版候选归零。
- 范围无法安全恢复时，异常会列出范围起止位置、Story 文本长度和 `getText` 返回长度，方便定位 SDK 差异。

## 0.5.0 更新

- 优先使用 `Story.getText(begin, length)` 读取节点范围；当前版本不可用时，再严格校验 `Story.text` / 全文读取回退，避免候选位置错位。
- 行首轮廓检测按 Unicode 码点而非 UTF-16 单元遍历，补充平面字符不会再导致轮廓数量错配；支持至 CJK 扩展 H 的汉字范围。
- 段落位置查询改为预建索引，长文本和大量发现项不再反复扫描文本前缀；连续 ASCII/全角空格混排也会被报告。
- 检查配置项并明确报告无效值；重叠的行首/连续标点挤压合并后限制在 `-1` 至 `0 em`，避免意外过度挤压。

## 使用方式

1. 在 Affinity 设置中启用 Scripting。
2. 在 Script Editor 中新建脚本。
3. 将 `Affinity_CJK_Typography_Toolkit.js` 全文粘贴进去并保存。
4. 在文档中选择一个或多个文本对象，运行脚本。
5. 在排版调整对话框中选择是否应用中西文字距或连续标点挤压，再阅读审校报告。

## 规则配置

打开 JS 文件顶部的 `CONFIG`：

```js
const CONFIG = {
  profile: 'zh-CN',
  maxExamplesPerCategory: 10,
  scanLinkedStoryOnce: true,
  cjkLatinSpacePolicy: 'review',
  cjkLatinAdjacency: 'review',
  checkAsciiPunctuation: true,
  checkRepeatedPunctuation: true,
  checkBracketPairs: true,
  checkParagraphBoundaries: true,
  checkRepeatedSpaces: true,
};
```

### `profile`

- `zh-CN`：简体中文（大陆）
- `zh-TW`：繁体中文（台湾）
- `ja-JP`：日文
- `custom`：自定义提示

规则集主要改变报告中的编辑提示。标点检查只检查 ASCII 标点与 CJK 字符直接相邻的情况，不会误扫英文句子内部的标点。

### `cjkLatinSpacePolicy`

- `review`：报告中西文之间的空格，提醒按全文规范统一（默认）。
- `ignore`：不报告单个中西文空格。
- `strict-no-space`：将中西文之间的空格列为待处理项。

### `cjkLatinAdjacency`

- `review`：报告中西文/数字直接相邻的位置，供人工检查视觉字距（默认）。
- `ignore`：关闭此类提示。

## 当前检查项目

- 段首标点或闭合符号
- 段末开括号或开引号
- 与 CJK 字符相邻的半角 ASCII 标点
- 连续重复标点
- 中英文及日文常见括号的嵌套、配对和顺序
- 中西文之间的空格策略
- 连续空格
- 中西文直接邻接的字距提示
- ASCII 空格与全角空格连续混排

## 可选字距微调

扫描到中西文/数字直接相邻时，会显示可调整位置数量。勾选后可设置字距增量，单位为 em，默认 `0.03`；正值增加间距，负值收紧间距。调整应用于每处边界左侧字符的字符间距属性，不会插入空格或更改文本内容。

## 连续标点挤压

- 在每对相邻标点之间应用负字偶距。仅匹配相邻且没有空格/换行的标点对，例如 `！！`、`？！`；`！ ！` 不算连续标点。
- 省略号（例如 `……`、`‥`、`...` 和 `．．．`）、破折号（例如 `——`）不会被挤压；汉字及汉字重复符号也不会作为挤压目标。
- 需手动勾选，增量允许在 `-1` 到 `0 em` 之间调整。文本内容保持不变。若控件显示 `0` 并禁用，表示当前选中文本中没有符合条件的标点对。

## 修复已有字距

在排版对话框中勾选“修复已有字距”，可将所选文本对象范围内的 `CharacterSpacing` 和 `ManualKerning` 设为 0。该选项用于清除此前脚本运行留下的异常字距，默认关闭；它也会清除范围内原本有意设置的手工字距。建议先复制文档，并在确认结果后再继续编辑。

所有排版调整默认不勾选，因此只运行审校时不会修改文档。确认应用的调整合并为单个 Affinity 撤销命令。结果报告会列出候选数量；应用失败或无法安全定位的情况会列入处理异常。

## 安全边界

本工具不自动替换标点、不删除空格、不插入空格，也不修改字体或段落格式。只有用户明确勾选后才写入字符间距或字偶距调整。

排版规则参考 [W3C 日本语组版要求](https://www.w3.org/TR/jlreq/) 的行首禁则约物说明；行轮廓定位和相邻字符 `ManualKerning` 用法参考 [Affinity 社区 `optical-kerning.js`](https://github.com/JiriKrblich/Affinity-Community-Scripts/blob/main/scripts/optical-kerning.js)。格式命令采用社区脚本中 `DocumentCommand`、`StoryDelta` 和 `TextSelection` 的模式。`Story.getText` / `StoryRange` 接口另与[社区维护的 Affinity 脚本类型定义](https://github.com/christippett/affinity-script-types)交叉核对；这些资料不是官方 SDK 规范，且可能随 SDK 版本变化。混合格式、链接文本框及撤销行为仍建议在实际文档中先行验证。
