# Affinity CJK Regex Tracking

**Version:** 0.8.4
**Target:** Affinity by Canva desktop scripting API (SDK 3.3.x)
**Platform:** macOS / Windows desktop
**License:** MIT

此脚本扫描文本，用正则查找中西文相邻字符和相邻标点，并把命中字符的 `CharacterSpacing`（Tracking）设为对应目标值。

## 调整范围

| 当前状态 | 调整范围 |
| --- | --- |
| 真正选中了文本字符 | 只调整选中的字符（最小单位） |
| 其它情况（未选中、只选中文本框、光标停在文本框内） | 整个文档（页面与可访问母版页） |

选区末位的字符仍会读取选区外的后一个字符来判断是否需要挤压，但只写入选区内的字符。控制台报告首行会写明本次是「选取项」还是「文档」。

| 规则 | Tracking |
| --- | --- |
| 中西文字符间距 | `250‰`（`0.25 em`） |
| 标点挤压 | `-500‰`（`-0.5 em`） |

数值集中在脚本顶部的 `TRACKING` 中，可直接修改：

```js
const TRACKING = {
  cjkLatin: 0.250,   // 中西文字符间距
  punctuation: -0.5, // 标点挤压
};
```

## 匹配规则

中日韩字符后接 ASCII 字母或数字：

```regex
[ぁ-ゖァ-ー\x{32FF}㍻-㍾\x{3400}-\x{4DBF}\x{4E00}-\x{9FFF}\x{F900}-\x{FAFF}](?=[0-9A-Za-z])
```

ASCII 字母或数字后接中日韩字符：

```regex
[0-9A-Za-z](?=[ぁ-ゖァ-ー\x{3400}-\x{4DBF}\x{4E00}-\x{9FFF}\x{F900}-\x{FAFF}])
```

点号（句号、逗号、顿号、分号、冒号、问号、叹号）后接任意中日韩标点：

```regex
[、。，．；：？！](?=[‘“〝（［｛〈《「『【〔〖〘〚”’〞〟）］｝〉》」』】〕〗〙〛、。，．；：？！])
```

后引号、后括号紧邻点号（例如 `”，`、`”。`、`」。`）：

```regex
[”’〞〟）］｝〉》」』】〕〗〙〛](?=[、。，．；：？！])
```

相邻标点的挤压结果：

| 文本片段 | 被挤压的字符 |
| --- | --- |
| `，”` | `，` |
| `”，` | `”` |
| `”，“` | `”` 与 `，`（开引号 `“` 不动） |
| `。”` | `。` |
| `」。` | `」` |

同一文本对象上的所有挤压目标会合并成**一条带多个范围的选择**写入，避免拆成多条命令时只生效一条。

标点挤压只作用于右侧留有空白的那一个字符：点号、后引号、后括号。开引号与开括号的空白在左侧，压缩它们只会让后续字形压到自身墨迹上，因此不参与挤压；引号、括号之间互不相邻点号时（如 `“「`、`”）`）也不压缩。省略号、破折号、波浪线不参与挤压。

脚本使用 JavaScript 正则查找匹配字符，再通过 Affinity 格式命令写入 Tracking。不会改写文本；已经是目标值的匹配项会跳过。运行时不弹对话框确认，统计与异常输出到脚本控制台。

Affinity 的 `Story.getLength()` 可能比 `Story.getText()` 读出的字符多一个（通常是末尾的段落标记）。脚本按可读区间处理这个差值，并用二分查找确认读不出的位置之前仍与 Story 坐标对齐，避免范围错位；控制台报告会列出按可读区间处理的文本范围数量。

## 跨页写入

文本格式命令只对**当前 spread** 生效，对其它 spread 上的节点执行会静默无效。脚本按目标节点所在的 spread 分桶，逐桶用 `DocumentCommand.createSetCurrentSpread` 切换当前 spread 后再写入，全部处理完后恢复你原来的 spread。因此一次运行即可覆盖整个文档，报告中的「涉及 spread：N 个」可用于确认。

## 母版页文本框

SDK 的 `doc.spreads` 只包含页面 spread，母版 spread 需要用 `NodeChildType.MasterSpread` 从根节点枚举（`doc.masterSpreads` 并不存在）。脚本按此枚举母版页文本框。

页面上从母版页文本框生成的文本对象与母版源共用同一个 Story。脚本按 Story 和字符位置找到覆盖该位置的母版源文本框（链式文本框也支持），把格式写到母版源节点上，页面实例随之更新；已脱离母版（独立 Story）的实例则写入自身节点。

写入时会准备多个候选节点（母版源、页面实例、以及同一 Story 上的全部文本对象）。命令执行后会回读 Tracking 校验：命令抛错或执行后没有生效，都会换下一个节点重试，全部无效才计失败，并在报告里写明每个节点的句柄、可编辑状态与原始错误信息。

控制台报告会给出：`母版页源文本框：X 个；页面母版实例：N 个；经母版文本框写入 Y 处、未匹配 Z 处`。未匹配非零且失败数不为零时，说明该处母版关系无法通过脚本识别。

调整写入文档格式，可用 Affinity 的撤销命令恢复。无法写入的项目会列入报告。
