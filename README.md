# Affinity CJK Typography Toolkit

**Version:** 0.5.12  
**Target:** Affinity by Canva desktop scripting API (SDK 3.3.x)  
**Platform:** macOS / Windows desktop  
**License:** MIT

## 简介

这是一个供 Affinity 桌面版使用的 CJK 文本审校脚本。它检查常见标点、括号、空格和中西文邻接问题，并提供可选的字距微调与连续标点挤压。审校只生成报告，不会自动改写文本；只有在调整对话框中勾选对应选项后，脚本才会修改字符间距或字偶距。

脚本按 Affinity SDK 3.3.x 编写。使用前请确认当前 Affinity 版本已启用 Scripting，并且已打开要检查的文档。

## 使用方式

1. 在 Affinity 设置中启用 Scripting。
2. 在 Script Editor 中新建脚本。
3. 将 `Affinity_CJK_Typography_Toolkit.js` 全文粘贴进去并保存。
4. 打开要处理的文档并运行脚本。
5. 选择文本查询范围：
   - **选取项**：仅扫描当前直接选中的文本对象（文本框或艺术字），不会把插入点所在文本自动视为选取项。
   - **文档**：扫描文档页面中的文本对象，以及 SDK 可访问的母版页文本对象。
6. 在排版调整对话框中查看候选数量；需要时勾选字距调整、连续标点挤压或已有字距重置，再确认运行。
7. 在 Affinity 脚本控制台查看审校报告。取消范围对话框会直接退出；取消调整对话框则只保留审校结果，不应用排版修改。

默认启用“选取项”范围，以保持针对选中对象快速检查的用法。文档扫描时会遍历页面与母版页节点；SDK 不提供 `masterSpreads` 时，会使用页面树回退。若某个节点读取失败，异常会记入报告，其他可访问节点仍会继续扫描。

## 规则配置

打开 JS 文件顶部的 `CONFIG`：

```js
const CONFIG = {
  profile: 'zh-CN',
  maxExamplesPerCategory: 10,
  scanLinkedStoryOnce: true,
  cjkLatinSpacePolicy: 'review',
  cjkLatinAdjacency: 'review',
  checkAsciiPunctuation: true,
  checkRepeatedPunctuation: true,
  checkBracketPairs: true,
  checkParagraphBoundaries: true,
  checkRepeatedSpaces: true,
};
```

### `profile`

- `zh-CN`：简体中文（大陆）
- `zh-TW`：繁体中文（台湾）
- `ja-JP`：日文
- `custom`：自定义提示

规则集主要改变报告中的编辑提示。标点检查只检查 ASCII 标点与 CJK 字符直接相邻的情况，不会误扫英文句子内部的标点。

### `cjkLatinSpacePolicy`

- `review`：报告中西文之间的空格，提醒按全文规范统一（默认）。
- `ignore`：不报告单个中西文空格。
- `strict-no-space`：将中西文之间的空格列为待处理项。

### `cjkLatinAdjacency`

- `review`：报告中西文/数字直接相邻的位置，供人工检查视觉字距（默认）。
- `ignore`：关闭此类提示。

### 其他配置

- `maxExamplesPerCategory`：报告中每个类别最多展示的示例数；设为 `0` 时隐藏示例，但仍统计全部发现项。
- `scanLinkedStoryOnce`：默认为 `true`，同一链接文本故事只审校一次，避免重复报告；设为 `false` 时按文本对象分别扫描，链接文本可能重复出现。
- `checkAsciiPunctuation`、`checkRepeatedPunctuation`、`checkBracketPairs`、`checkParagraphBoundaries`、`checkRepeatedSpaces`：分别启用或关闭对应类别的检查。每项必须为布尔值。
- 配置值会在运行时校验；无效配置会提示错误并停止扫描。

## 当前检查项目

- **段首标点**：忽略段首空白后，提示以常见标点或闭合符号开头的非空段落。
- **段末标点**：提示以开括号或开引号结尾的非空段落。
- **半角标点**：提示英文逗号、句点、分号、冒号、感叹号或问号紧邻 CJK 字符的情况；英文标点位于英文单词之间时不会因此单独报警。
- **连续标点**：报告重复出现的同一种标点，例如 `！！`。这是审校提示，不会自动删除或替换标点。
- **括号配对**：检查常见中英文括号、方括号、书名号和引号的配对及嵌套顺序；将重复的段首「识别为跨段对话引号延续。
- **中西文空格**：按 `cjkLatinSpacePolicy` 检查 CJK 与 ASCII 字母/数字之间的空格；CJK 字符之间的空格也会提示。
- **重复空格**：检查连续 ASCII 空格或全角空格，包括两种空格混排。
- **中西文邻接**：提示没有空格分隔的 CJK 与 ASCII 字母/数字边界，供人工判断视觉字距。

每类发现会提供文本对象标签、上下文示例、字符串索引和段落序号。报告索引采用 UTF-16 偏移；文本按 Unicode 字符计数。

## 可选字距微调

扫描到中西文/数字直接相邻时，会显示可调整位置数量。勾选后可设置字距增量，单位为 em，默认 `0.25`，允许范围为 `-0.5` 至 `0.5`；正值增加间距，负值收紧间距。增量应用于每处边界左侧字符的 `CharacterSpacing` 属性，不会插入空格或更改文本内容。没有候选位置时，该选项会禁用。

## 连续标点挤压

- 在每对相邻且可压缩的标点之间应用 `ManualKerning`（字偶距）增量。只处理紧邻且没有空格或换行的标点对，例如 `！！`、`？！`；`！ ！` 不会作为一对处理。
- 省略号（例如 `……`、`‥`、`...` 和 `．．．`）、破折号（例如 `——`）以及波浪号（例如 `〜`、`～`）不会被挤压；汉字及汉字重复符号也不会作为挤压目标。
- 需手动勾选，增量允许在 `-1` 到 `0 em` 之间调整，默认值为 `-0.5 em`。文本内容保持不变；没有匹配项时该选项会禁用。

## 修复已有字距

在排版对话框中勾选“修复已有字距”，可将当前查询范围内文本范围的 `CharacterSpacing` 和 `ManualKerning` 设为 `0`。默认关闭。此操作会一并清除范围内原本有意设置的手工字距，不只清除本脚本写入的值；建议先复制文档并确认结果。

所有排版调整默认不勾选，因此只运行审校时不会修改文档。批量调整成功时通常合并为一个 Affinity 撤销命令；若批量命令失败，脚本会隔离到文本对象或位置逐项重试，成功项可能需要分别撤销。结果报告会列出扫描范围、候选数量及处理异常；部分节点失败不会被当作整体成功隐藏。

## 报告与问题排查

- 报告写入 Affinity 脚本控制台，不额外弹出完成提示框。
- 报告中的“扫描文本故事”会按默认设置去重链接文本故事；“扫描字符”按 Unicode 字符计数。
- 如果某类调整数量为 `0` 或相应选项不可用，表示当前扫描范围内没有检测到可调整目标。
- 如果提示没有可扫描的文本对象，请检查是否选中了文本对象，或改用“文档”范围。
- `处理异常` 会列出文本读取、范围校验或格式命令失败信息。文档扫描遇到局部异常时，其他可读取的节点仍会被处理。
- 字距重置会清除原有手工字距；应用前建议保存副本，并确认所选扫描范围正确。

## 安全边界

本工具不自动替换标点、不删除空格、不插入空格，也不修改字体或段落格式。只有用户明确勾选后才写入字符间距或字偶距调整。

排版规则参考 [W3C 日本语组版要求](https://www.w3.org/TR/jlreq/) 的行首禁则约物说明；行轮廓定位和相邻字符 `ManualKerning` 用法参考 [Affinity 社区 `optical-kerning.js`](https://github.com/JiriKrblich/Affinity-Community-Scripts/blob/main/scripts/optical-kerning.js)。格式命令采用社区脚本中 `DocumentCommand`、`StoryDelta` 和 `TextSelection` 的模式。文档范围的 spread 遍历与文本 API 按 [Affinity SDK 官方文档](https://sdk.affinity.studio/latest/)（本次核对版本 3.3.3）及 SDK 内置 JSLib 用法实现，并针对本机 Affinity 3.3.1 的 JSLib 保留了 `masterSpreads` 不可用时的回退。`Story.getText` / `StoryRange` 接口另与[社区维护的 Affinity 脚本类型定义](https://github.com/christippett/affinity-script-types)交叉核对；混合格式、链接文本框及撤销行为仍建议在实际文档中先行验证。
